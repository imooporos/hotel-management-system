# 7. Руководство администратора

## 7.1 Роли системы

| Роль | Описание | Функционал |
|------|----------|-----------|
| guest | Гость | Просмотр номеров, бронирование, профиль |
| manager | Менеджер | + управление бронированиями, отчёты |
| admin | Администратор | + управление пользователями, аудит-лог |

## 7.2 Вход в административную панель

1. Войдите в систему с учётной записью менеджера или администратора.
2. В боковой панели навигации появится пункт **«Управление»**.
3. Нажмите на **«Управление»** для перехода в админ-панель.

Тестовые учётные записи:
- Администратор: `admin@hotel.local` / `Admin123!`
- Менеджер: `manager@hotel.local` / `Manager123!`

## 7.3 Управление бронированиями

Вкладка **«Бронирования»** отображает все бронирования в системе.

### Просмотр бронирований
- Список содержит: номер бронирования, гость, номер комнаты, даты, статус, сумму.
- Бронирования отсортированы по дате создания (новые сверху).

### Смена статуса
Доступные переходы между статусами:

```
pending → confirmed → checked_in → checked_out
    ↓         ↓
 cancelled  cancelled
```

Для смены статуса:
1. Найдите бронирование в списке.
2. Нажмите кнопку с новым статусом (✓ подтвердить, ✗ отменить).
3. Система проверит допустимость перехода.

## 7.4 Управление пользователями (только admin)

Вкладка **«Пользователи»** доступна только администраторам.

### Просмотр пользователей
Таблица содержит:
- ID, ФИО, Email, Роль
- Статус активности (активен / заблокирован)
- Дата регистрации

### Смена роли
1. Найдите пользователя в списке.
2. Выберите новую роль из выпадающего списка: guest / manager / admin.
3. Нажмите **«Сохранить»**.

### Блокировка пользователя
1. Нажмите кнопку **блокировки** напротив пользователя.
2. Заблокированный пользователь не сможет войти в систему.
3. Для разблокировки нажмите кнопку повторно.

## 7.5 Отчёты (manager, admin)

Вкладка **«Отчёты»** предоставляет аналитику.

### Отчёт по выручке
Содержит:
- Выручку по категориям номеров
- Количество бронирований в каждой категории
- Среднюю стоимость бронирования
- Общую выручку

Данные формируются на основе представления `v_revenue_by_category`.

### Загрузка гостиницы
- Процент загрузки за выбранный период.
- Рассчитывается функцией `fn_occupancy_rate`.

## 7.6 Аудит-лог (только admin)

Вкладка **«Аудит»** отображает журнал всех изменений.

### Содержимое записей
| Поле | Описание |
|------|----------|
| Дата/время | Метка времени изменения |
| Таблица | Имя таблицы (bookings, users, ...) |
| Действие | INSERT / UPDATE / DELETE |
| ID записи | Идентификатор изменённой записи |
| Старые данные | JSON до изменения |
| Новые данные | JSON после изменения |
| Пользователь | Кто внёс изменения |

### Назначение
Аудит-лог позволяет:
- Отслеживать кто и когда изменял данные.
- Восстановить историю изменений бронирования.
- Обнаружить несанкционированные действия.
- Проводить расследование инцидентов.

## 7.7 Развёртывание сервера

### Системные требования
- Ubuntu 22.04 LTS
- PostgreSQL 16
- Python 3.11+
- Минимум 1 ГБ RAM, 10 ГБ диска

### Установка

```bash
# 1. Установить PostgreSQL 16
sudo apt install -y postgresql-16

# 2. Инициализировать БД
cd pg_scripts && bash reset.sh

# 3. Установить зависимости Python
cd ../server
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

# 4. Настроить переменные окружения
export DATABASE_URL="postgresql://hotel_app:hotel_secure_pwd_2025@localhost:5432/hotel_db"
export JWT_SECRET="your-secret-key-here"
export CORS_ORIGINS="*"

# 5. Запустить сервер
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Systemd-сервис

```ini
[Unit]
Description=Hotel Management API
After=postgresql.service

[Service]
User=www-data
WorkingDirectory=/opt/hotel/server
Environment=DATABASE_URL=postgresql://hotel_app:hotel_secure_pwd_2025@localhost:5432/hotel_db
Environment=JWT_SECRET=your-secret-key
Environment=CORS_ORIGINS=*
ExecStart=/opt/hotel/server/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

## 7.8 Резервное копирование

```bash
# Полный дамп базы данных
pg_dump -U hotel_app -d hotel_db -F c -f backup_$(date +%Y%m%d).dump

# Восстановление из дампа
pg_restore -U hotel_app -d hotel_db -c backup_20250101.dump
```

Рекомендуется выполнять ежедневное резервное копирование через cron.
