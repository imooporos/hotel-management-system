# Руководство пользователя — Velmar Hotel

## Назначение

Информационная система **Velmar Hotel** предназначена для:

- бронирования гостиничных номеров через личный кабинет;
- ведения базы клиентов и их бронирований;
- управления номерным фондом, услугами, пользователями;
- получения PDF-документов (бланк заказа, отчёты);
- учёта изменений в системе через журнал аудита.

Система реализована как клиент-серверное приложение:

- **Сервер** (FastAPI + PostgreSQL) — http://77.221.151.85
- **Клиент** (Flet, Python) — кроссплатформенный (Windows / Linux / macOS / Web)

## 1. Запуск клиента

### 1.1 Установка

```bash
git clone https://github.com/imooporos/hotel-management-system.git
cd hotel-management-system/client
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
```

### 1.2 Запуск

Native-окно:

```bash
python -m hotel_client
```

В браузере:

```bash
python -m hotel_client --web --port 8550
# открыть http://localhost:8550
```

По умолчанию клиент подключается к `http://77.221.151.85`.
Для изменения адреса используйте флаг `--api-url` или переменную `HOTEL_API_URL`:

```bash
python -m hotel_client --api-url http://localhost:8000
```

## 2. Группы пользователей

В системе три роли:

| Роль       | Возможности |
|------------|-------------|
| **Гость**  | Регистрация, вход, просмотр и редактирование профиля, просмотр номеров, бронирование, отмена брони, скачивание PDF-бланка |
| **Менеджер** | Всё, что у гостя, + просмотр всех бронирований, изменение статусов (подтверждение, заселение, выписка), отчёты по выручке и загрузке |
| **Администратор** | Всё, что у менеджера, + управление пользователями (роли, активность), журнал аудита |

Тестовые учётки:

| Роль | Логин | Пароль |
|------|-------|--------|
| Гость | `ivanov@example.com` | `Guest_2026!` |
| Менеджер | `manager@hotel.local` | `Manager_2026!` |
| Админ | `admin@hotel.local` | `Admin_2026!` |

## 3. Сценарии для гостя

### 3.1 Регистрация / Вход

1. На стартовом экране нажмите **«Зарегистрироваться»** (или **«Войти»** при наличии аккаунта).
2. Введите email, ФИО и пароль (минимум 8 символов).
3. После успешной регистрации сразу окажетесь в каталоге номеров.

### 3.2 Просмотр / редактирование профиля

1. Кликните на имя пользователя в шапке → **«Профиль»**.
2. Поля «ФИО» и «Телефон» доступны для редактирования. Email менять нельзя.
3. Нажмите **«Сохранить изменения»** — изменения мгновенно отражаются в БД (через триггер `trg_set_updated_at` обновляется `updated_at`).

### 3.3 Поиск и фильтрация номеров

В разделе **«Номера»** доступны фильтры:

- категория (Стандарт, Стандарт+, Полулюкс, Люкс, Семейный);
- цена «от» / «до»;
- минимальное количество гостей;
- даты заезда / выезда — отфильтровывает только номера, свободные на этот период (через PostgreSQL-функцию `fn_room_is_free`).

### 3.4 Создание брони

1. На карточке номера нажмите **«Забронировать»**.
2. Укажите даты заезда / выезда, количество гостей.
3. (Опционально) выберите дополнительные услуги — общая стоимость пересчитывается на лету (вызов `fn_calculate_booking_total`).
4. Можно оставить комментарий администратору.
5. Нажмите **«Подтвердить бронирование»**.

Если на выбранные даты номер занят, форма покажет ошибку «занято — выберите другие даты».

### 3.5 Просмотр и отмена своих бронирований

1. В шапке выберите **«Мои брони»**.
2. Каждая бронь — отдельная карточка со статусом, количеством ночей, итоговой суммой и оплаченной суммой.
3. Кнопка **«Скачать PDF»** — формирует и сохраняет бланк заказа в `~/Downloads`.
4. Кнопка **«Отменить»** доступна для броней в статусах *Ожидает подтверждения* и *Подтверждена*.

## 4. Сценарии для менеджера

### 4.1 Управление бронированиями

В разделе **«Администрирование» → «Бронирования»**:

| Текущий статус | Доступные действия |
|----------------|---------------------|
| pending (Ожидает) | Подтвердить, Отменить |
| confirmed (Подтверждено) | Заселить, Отменить |
| checked_in (Заселён) | Выписать |
| checked_out / cancelled | — (терминальные статусы) |

При смене статуса срабатывает триггер `trg_update_room_status`, который автоматически переводит сам **номер** в соответствующее состояние (`reserved` / `occupied` / `cleaning` / `available`).

### 4.2 Отчёты

Раздел **«Отчёты»** содержит:

- **Загрузка фонда** — процент занятости номеров за период (источник: `fn_occupancy_rate`).
- **Выручка по категориям** — таблица: количество броней, общая сумма, оплачено (источник: представление `v_revenue_by_category`).

Каждый отчёт можно скачать в формате PDF (через ReportLab с поддержкой кириллицы).

## 5. Сценарии для администратора

### 5.1 Управление пользователями

**«Администрирование» → «Пользователи»** — таблица всех пользователей с возможностью:

- сменить роль (гость / менеджер / админ);
- активировать или деактивировать учётку;
- сохранить изменения по нажатию кнопки.

### 5.2 Журнал аудита

**«Администрирование» → «Журнал аудита»** — список всех изменений в трёх ключевых таблицах:

- `bookings`
- `users`
- `rooms`

Для каждой записи показаны: время, таблица, ID записи, тип операции (INSERT / UPDATE / DELETE), пользователь.

Журнал ведётся автоматически через триггеры `trg_audit_*`. Это критично для **методов защиты данных** — даёт возможность расследовать инциденты и восстанавливать исходное состояние.

## 8. Решение типичных проблем

| Симптом | Решение |
|---------|---------|
| «Номер занят на указанные даты» | Выберите другие даты — триггер защитил БД от перекрывающихся бронирований |
| «Срок действия токена истёк» | Войдите заново. Токен живёт 12 часов |
| «Доступ только для ролей: …» | У вас нет прав на эту операцию. Обратитесь к администратору |
| Не открывается клиент | Проверьте, что Python ≥ 3.11 и установлены зависимости из `client/pyproject.toml` |
| API недоступно | Проверьте http://77.221.151.85/health — должен вернуть `{"status":"ok"}` |
