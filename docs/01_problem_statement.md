# 1. Постановка задачи

## 1.1 Предметная область

Информационная система управления гостиницей «Гранд Отель» предназначена для автоматизации процессов бронирования номеров, управления гостевым фондом, учёта дополнительных услуг и формирования отчётной документации.

Гостиничный бизнес требует оперативного контроля загрузки номерного фонда, быстрой обработки заявок на бронирование, учёта персональных данных гостей и прозрачного ведения финансовой отчётности. Ручное управление этими процессами приводит к ошибкам, дублированию записей и потере данных.

## 1.2 Цели проекта

1. Разработать клиент-серверное приложение для управления гостиницей.
2. Спроектировать и реализовать реляционную базу данных PostgreSQL с полным набором объектов: домены, пользовательские типы (ENUM), таблицы, индексы, представления, функции, хранимые процедуры, триггеры.
3. Реализовать систему разграничения прав доступа на нескольких уровнях: приложение (JWT + RBAC), БД (GRANT/REVOKE), строки (RLS).
4. Обеспечить формирование отчётных документов в формате PDF.
5. Развернуть серверную часть на удалённом сервере.

## 1.4 Требования к системе

### Функциональные требования

- **FR-01**: Регистрация и авторизация пользователей по email и паролю.
- **FR-02**: Просмотр и редактирование личного кабинета (ФИО, телефон, паспортные данные).
- **FR-03**: Просмотр каталога номеров с фильтрацией по категории, вместимости, цене.
- **FR-04**: Создание бронирования с выбором дат заезда/выезда, количества гостей, дополнительных услуг.
- **FR-05**: Автоматическая проверка пересечения дат бронирования (trigger + exclusion constraint).
- **FR-06**: Формирование и скачивание бланка заказа (PDF).
- **FR-07**: Управление статусами бронирований (подтверждение, заезд, выезд, отмена).
- **FR-08**: Управление пользователями (смена ролей, блокировка).
- **FR-09**: Формирование отчётов: выручка по категориям, загрузка номерного фонда.
- **FR-10**: Ведение аудит-лога всех изменений в бронированиях.

### Нефункциональные требования

- **NFR-01**: Время отклика API — не более 500 мс для 95% запросов.
- **NFR-02**: Поддержка одновременной работы не менее 50 пользователей.
- **NFR-03**: Хранение паролей в виде bcrypt-хэшей (cost factor 12).
- **NFR-04**: Кроссплатформенность клиента: Desktop (Windows / macOS / Linux), Web, iOS, Android.
- **NFR-05**: Совместимость с PostgreSQL 14+.

## 1.6 Используемые технологии

- **СУБД**: PostgreSQL 16
- **Backend**: Python 3.11+, FastAPI, asyncpg, Pydantic v2
- **Frontend**: Python 3.11+, Flet (Flutter-based)
- **Аутентификация**: JWT (HS256) + bcrypt
- **Отчёты**: ReportLab (PDF)
- **Тестирование**: pytest, httpx
- **Развёртывание**: Debian 12, systemd, nginx
